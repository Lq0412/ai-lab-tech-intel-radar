## 二、线上面试准备规划

### 1. 面试表达结构

20 分钟面试可以按这个节奏讲：

| 时间 | 内容 |
| --- | --- |
| 0-2 分钟 | 说明你对题目的理解：核心是技术情报降噪 |
| 2-6 分钟 | 讲 MVP 架构：信息源、Pipeline、人工审核、周报 |
| 6-10 分钟 | 讲关键取舍：不用 Agent、不做 Dashboard、保留人工审核 |
| 10-14 分钟 | 讲 4 周落地计划 |
| 14-20 分钟 | 回答追问 |

### 2. 面试时要突出的人设

你需要呈现的是：

- 能用 LLM，但不迷信 LLM。
- 能做架构，但知道 MVP 要收敛。
- 关注工程落地，而不是只讲概念。
- 能接受需求不清晰，并主动提出假设。
- 能把复杂 AI 信息转成决策者能读懂的报告。

### 3. 不建议主动展开的内容

这些内容除非被问到，否则不要主动讲太多：

- 复杂 Agent 编排。
- 大规模向量数据库。
- 多平台社交媒体爬取。
- 实时 Dashboard。
- 自动化技术决策。

原因是它们容易让面试官觉得方案过重，和 4 周 MVP 约束冲突。

## 三、如果通过筛选后的 4 周落地规划

### Week 1：跑通单源闭环

目标：

- 先用 GitHub 一个信息源跑通完整流程。

产出：

- Python 项目骨架。
- SQLite 数据表。
- GitHub 采集脚本。
- 统一数据结构 `TechItem`。
- 第一份人工触发的候选列表。

验收标准：

- 能从 GitHub 拉取真实项目数据。
- 能存入 SQLite。
- 能导出 Markdown 候选列表。

### Week 2：多源采集和降噪

目标：

- 接入 Hugging Face 和 RSS。
- 建立基础去重和过滤规则。

产出：

- Hugging Face 采集器。
- RSS 采集器。
- URL 去重。
- 标题相似度合并。
- 配置化关键词和阈值。

验收标准：

- 三类来源都能稳定采集。
- 重复项明显减少。
- 过滤规则可以通过配置调整。

### Week 3：LLM 分析和周报生成

目标：

- 接入 LLM 完成分类、摘要、评分和能力边界分析。

产出：

- Prompt 模板。
- LLM 分析模块。
- Markdown 周报模板。
- 初版 Top 推荐列表。

验收标准：

- 每条候选情报都有分类、摘要、评分、能力边界。
- 能生成一份完整周报。
- 人工可以直接修改周报内容。

### Week 4：内测、复盘和交付

目标：

- 用真实数据跑 2-3 轮，调整规则并形成可交接版本。

产出：

- 使用说明。
- 配置说明。
- 运行日志。
- 2-3 份真实周报样例。
- 下一阶段迭代建议。

验收标准：

- Lab 成员能独立运行。
- 周报内容能被讨论和采纳。
- 系统问题、误判类型、后续优化方向有记录。

## 四、优先级排序

如果时间不够，优先保证：

1. 方案文档清晰完整。
2. 架构图能解释清楚。
3. 关键取舍讲得有理有据。
4. 4 周计划可信。
5. LLM 使用说明真实。

可以放弃：

1. 复杂 UI。
2. 太多信息源。
3. Agent 主流程。
4. 自动化深度研究。
5. 大而全的平台化设想。

## 五、最终判断标准

这份任务不是看你能不能想出最复杂的系统，而是看你是否具备以下能力：

- 能识别真实需求。
- 能在约束下做取舍。
- 能把 AI 工具用于实际工作。
- 能设计可落地的 MVP。
- 能把技术方案讲给决策者听。

所以接下来的重点不是继续堆功能，而是把当前方案打磨到“清楚、可信、可落地、可追问”的状态。
